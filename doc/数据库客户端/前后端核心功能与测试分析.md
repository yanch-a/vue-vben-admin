## 2. 核心功能地图

### 2.1 数据库连接与权限

1. 保存数据库连接配置：数据库类型、JDBC 地址、主机、端口、账号、密码、SSH/代理等。
2. 测试连接并读取数据库实例、表、列、主键、索引、视图、过程、函数等元数据。
3. 通过连接权限控制使用权限、数据写权限、结构写权限和管理权限。
4. 连接信息和敏感字段由后端持久化，前端只负责选择连接和实例，不应把凭据写入 SQL 或日志。

### 2.2 数据库对象树

前端对象树以连接为根，按产品方言展示实例、表、视图、过程、函数等对象。右键菜单包含打开表、查看表结构、生成 DDL、导出结构/数据、复制数据库、删除或清空等操作。对象树的关键前提是：实例在不同产品中的含义不同，不能把所有实例都当成 schema。

### 2.3 SQL 编辑器

SQL 编辑器使用 Monaco，支持查询 Tab、格式化、补全、历史 SQL、保存查询、执行计划、结果区联动和 AI 辅助。执行路径分为：

- 查询：`executeSql`，后端做只读校验、限行、元数据和结果返回。
- DML：`executeDml`，用于 INSERT、UPDATE、DELETE 等数据写操作。
- DDL：单独的 DDL 执行和管理权限校验。
- SQL 脚本：上传文件后转后台异步任务执行。

前端方言差异统一收敛在 `resolveSqlDialect(dbType)`，后端则按 `SqlDialectFamily` 和具体 `DataBaseType` 选择 Handler、JDBC URL 和元数据策略。

### 2.4 查询结果与表格编辑

结果面板支持复制、导出、分页/滚动查看、单元格编辑、整行编辑、删除和新增。单表查询按主键生成 UPDATE/DELETE；联表查询先解析 `FROM/JOIN`、SELECT 列提示和 JDBC `columnTables`，再把修改列分组到各物理表，按各表主键分别生成 UPDATE。

联表编辑的设计约束是：

- 被修改的物理表必须有主键。
- 结果集中必须带上该表主键。
- 同名字段必须在 SELECT 中用表别名或 `AS` 区分。
- 计算列、聚合列、表达式列、无法确定归属的列不应允许更新。

### 2.5 异步任务

复制数据库、导出结构、SQL 脚本和结构文档使用后端任务或前端轮询。SQL 脚本任务保存到 Redis，前端 `useClientTasks` 统一显示进行中、成功、部分失败、失败和取消状态。

### 2.6 AI 与扩展能力

AI 模块包括 SQL 生成/解释、结构文档、历史分析、Agent 会话和图表。它们依赖当前数据库连接和实例上下文，后续排查 AI 生成 SQL 时也应复用本文的方言、权限和只读校验边界。

## 3. 数据库兼容模型

当前后端枚举共有 17 个产品，实际复用 6 个方言族和多个 JDBC Handler：

| 方言族 | 产品 |
| --- | --- |
| MYSQL_LIKE | MySQL、OceanBase、OceanBase MySQL、TDSQL、PolarDB、PolarDB MySQL |
| POSTGRES_LIKE | PostgreSQL、KingbaseES、HighGo DB、GaussDB/openGauss、PolarDB PostgreSQL |
| ORACLE_LIKE | Oracle、Dameng、OceanBase Oracle |
| SQLSERVER_LIKE | Microsoft SQL Server |
| SQLITE_LIKE | SQLite |
| H2_LIKE | H2 |

这里的“复用 Handler”不等于完全兼容。产品兼容至少要分别验证：连接 URL、实例/schema 语义、标识符引用、分页/限行、元数据、主键识别、DDL/DML、存储过程/触发器脚本和 JDBC 驱动返回的列信息。

主要后端实现位置：

- 产品枚举：`lemon-platform/lemon-common/src/main/java/com/lemon/common/enums/DataBaseType.java`
- 产品注册和 JDBC 配置：`lemon-other/lemon-visual-query/src/main/java/com/lemon/vq/dialect/DbTypeProfiles.java`
- 方言族：`lemon-other/lemon-visual-query/src/main/java/com/lemon/vq/dialect/SqlDialectFamily.java`
- 操作 Handler：`lemon-other/lemon-visual-query/src/main/java/com/lemon/vq/service/handler/`
- 前端产品和方言：`apps/web-ele/src/views/visual/client/dialect/`

特别注意：MySQL 的 instance 通常是 database，PostgreSQL/SQL Server 的 instance 更接近 database，而 H2/SQLite/达梦/Oracle 的 schema、服务名和连接 URL 语义不同。结果编辑、元数据请求和表名限定必须一直使用方言策略，不能直接拼接 instance。

## 4. SQL 脚本执行流程

### 4.1 前端

1. `SqlScriptUploadDialog.vue` 校验连接、实例、扩展名、编码和是否遇错继续。
2. `api/visual/sqlScript.ts` 以 multipart 调用 `/admin/sqlScript/start`。
3. `useClientTasks.ts` 保存任务并轮询 `/tasks` 和 `/task/{id}`，支持取消。
4. 任务面板显示当前 SQL、完成数、成功数、失败数和错误列表。

### 4.2 后端

1. `SqlScriptController` 接收上传文件、连接 ID、实例、编码和 continueOnError。
2. `SqlScriptOrchestrator` 校验登录、连接使用权、写权限、文件类型、方言并调用 `SqlScriptSplitter`。
3. `SqlScriptTaskManager` 把任务和用户索引放入 Redis，单用户最多 2 个运行任务。
4. 异步线程通过 `IDataBaseOperateService.executeSqlScript` 逐句执行，实时更新进度。
5. 分割器按方言处理普通分号、MySQL `DELIMITER`、SQL Server `GO`、Oracle 斜杠行、PL/SQL、PG/H2 dollar quote、SQLite/H2 block。

### 4.3 当前重要语义

- 每条语句在同一个 JDBC 连接中执行，但当前显式设置 `autoCommit=true`，不是整文件事务。
- `continueOnError=true` 是逐条执行并最终显示部分失败。
- `continueOnError=false` 预期是第一条失败后停止。
- 当前脚本入口允许 DDL、DML 和查询混合，因此权限和危险语句分类必须在脚本入口重新校验，不能只依赖单条 DDL API。

## 5. 当前代码审计结果

### P1：SQL 脚本权限检查不能覆盖脚本内的语句类型

证据：`SqlScriptOrchestrator.start` 只要求 `canWriteSchema || canWriteData`，随后把分割出的全部语句交给 `executeSqlScript`。`AbstractDataBaseOperateService.executeSqlScript` 只调用 `SqlDdlValidator.rejectForbidden(sql)`，该校验主要拦截 OUTFILE、DUMPFILE、LOAD DATA、SLEEP、BENCHMARK 等危险片段，并没有按语句类型执行管理权限校验。

影响：只有数据写权限的用户，理论上可能通过脚本提交 `DROP DATABASE`、`CREATE USER`、`GRANT`、`REVOKE`、`ALTER USER` 等管理/高危语句；只有结构写权限的用户也可能执行不应允许的数据或查询操作。需要在脚本入口对每条语句分类，至少复用 `SqlDdlValidator.requiresManagePrivilege` 和 DML/查询分类，并根据权限拒绝不匹配的脚本。

参考：

- `lemon-other/lemon-visual-query/src/main/java/com/lemon/vq/sqlscript/service/SqlScriptOrchestrator.java:73`
- `lemon-other/lemon-visual-query/src/main/java/com/lemon/vq/service/impl/AbstractDataBaseOperateService.java:927`
- `lemon-other/lemon-visual-query/src/main/java/com/lemon/vq/utils/SqlDdlValidator.java`

### P1：continueOnError=false 提前停止后会伪装成执行完全部语句

`onError` 在第一条失败时返回 `false`，JDBC 循环正常返回；但 `runTask` 后续无条件执行 `done.setDone(done.getTotal())`，并按成功/失败数重新覆盖消息。因此一个 10 条脚本第 3 条失败的任务，可能显示 done=10，消息变成“部分完成”或“全部失败”，而不是“第 3 条失败，已停止”。

参考：

- 停止信号：`SqlScriptOrchestrator.java:192-195`
- 无条件完成：`SqlScriptOrchestrator.java:214-238`

建议保留实际已处理数量，增加明确的 STOPPED/FAILED 状态或至少在 `continueOnError=false` 且已停止时保留 `done` 和停止消息。

### P1：联表结果中的计算列可能被误判为可更新

`resultRowSql.ts` 对 `COALESCE(u.name, '') AS name`、CASE、函数和其它带括号的表达式只保留结果名，没有物理列信息。`resultJoinUpdate.ts` 随后在 JDBC `columnTables` 存在时回退到 `resultCol` 作为物理列名。如果 JDBC 报告该列来自 `users`，就会把表达式别名 `name` 误认为 `users.name` 并生成 UPDATE。

已用临时 Vitest 用例复现：普通联表两张表按主键各生成一条 UPDATE 的用例通过；计算列在 JDBC 返回 `users` 时本应抛错，但当前实现没有抛错。该临时测试文件已删除，避免把预期失败用例留在工作区。

参考：

- `apps/web-ele/src/views/visual/client/utils/resultRowSql.ts:260-290`
- `apps/web-ele/src/views/visual/client/utils/resultJoinUpdate.ts:76-148`

建议：对表达式/聚合/窗口函数/CASE/子查询列保留 `isWritable=false`，归属解析只允许明确的物理列提示；不要用结果别名回退成物理列名。

### P2：multipart Content-Type 被前端手动写死

`startSqlScript` 在传入 `FormData` 时显式设置 `Content-Type: multipart/form-data`。浏览器通常需要自动附加 boundary；如果请求库不主动修正这个 header，Spring MultipartResolver 可能无法解析上传内容。建议删除这个 header，让 fetch/axios/request 库根据 `FormData` 自动生成。

参考：`apps/web-ele/src/api/visual/sqlScript.ts:32-39`，以及请求透传：`apps/web-ele/src/utils/request.ts:18-38`。

### P2：文件超限回调的类型和值不一致

`ElUpload` 的 `on-exceed` 回调收到的是 `UploadRawFile[]`，当前 `onExceed(files: File[])` 直接把第一项赋给 `form.file`。正常选文件走 `file.raw`，超限替换路径却可能把包装对象而不是原始 `File` 放入 FormData，导致上传内容异常。应统一取 `files[0].raw` 或使用正确的 Element Plus 类型。

参考：`apps/web-ele/src/views/visual/client/components/SqlScriptUploadDialog.vue:50-60`。

### P2：脚本执行是逐条提交，用户需要看到部分提交语义

后端显式 `autoCommit=true` 且没有整文件回滚。脚本中前几条成功、后面失败时，成功部分会保留。这个行为本身可以是产品选择，但前端的“执行完成/部分失败”提示和文档必须明确“不是原子事务”；否则用户容易把失败重试当成安全回滚。

参考：`AbstractDataBaseOperateService.java:933-965`。

### P2：公共包类型检查存在既有阻塞

`pnpm -F @vben/web-ele typecheck` 失败在 `packages/effects/access/src/accessible.ts:147`：`RouteRecordRaw | null` 不能传给 `RouteRecordRaw | undefined`。这不是本次新增 SQL 脚本或结果编辑文件引入的错误，但会阻塞把类型错误作为 CI 门禁。

## 7. 建议的下一轮验收矩阵

每个产品至少准备一个隔离测试库和一组非破坏性测试表，逐产品执行以下用例：

1. 测试连接、列出实例、列出表、读取列和主键。
2. 查询单表并编辑普通字段、编辑 NULL、编辑带引号/Unicode 的值。
3. 联表查询分别修改两张表字段，验证两条 UPDATE 的表名、列名和主键 WHERE。
4. 联表查询修改同名列、计算列、聚合列、重复主键列，均应拒绝或要求明确别名。
5. SQL 脚本执行普通 DDL、DML、查询、注释、字符串内分号和该产品的过程/触发器语法。
6. `continueOnError=true/false` 分别测试首条失败、中间失败、末条失败、取消和重复轮询。
7. 权限矩阵分别使用只读、数据写、结构写、管理权限账号，确认脚本中的查询、DML、DDL、用户/授权语句不会越权。
8. 检查提交后数据：明确记录逐条提交或事务回滚，不只检查任务状态。

## 8. 当前结论

构建层面，前端生产构建和后端模块测试是通的，脚本分割器的已有方言冒烟覆盖也通过。功能层面目前不建议直接宣称“17 个数据库全部兼容”：脚本入口的权限分类、停止后的进度状态、联表计算列误更新是优先修复项；multipart boundary 和超限文件回调是优先验证项。真实多库测试需要先提供可连接的隔离实例或在工作台建立已登录测试连接，再按第 7 节矩阵逐库执行。
